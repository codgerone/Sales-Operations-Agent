# 文档地图

| 文档 | 回答什么问题 | 你需要读吗 |
|---|---|---|
| [vision.md](vision.md) | 项目要做成什么、为谁解决什么、遵循哪些原则、范围与不做什么 | **需要**，目标或范围变化时看改动 |
| [roadmap.md](roadmap.md) | 分几个阶段、每个版本做什么、开工时要确定什么 | 选下一个版本时看 |
| `changes/` | 进行中的版本提案：需要你拍板的问题、目标、改什么、不改什么、怎么验收。为空表示当前没有进行中的版本 | **主要审核入口** |
| `overview.md`（V1.1 起） | 系统现在能做什么、怎么运行、怎么验收 | **需要**，系统变化时看改动 |
| `design.md`（V1.1 起） | 架构、数据模型、各模块职责与关键机制 | 面试复盘时读 |
| `rules/`（按需） | 业务规则与算法细则：日期计算、匹配判定、校验规则、评测指标定义 | 只看每份开头的规则摘要 |
| `decisions/`（按需） | 重要决策的背景、选项与结论 | 新增决策时看 |
| `archive/` | `history.md`：各版本演进与指标；`changes/`：已完成版本的提案与实施结果 | 需要时 |
| [../learning/](../learning/README.md) | 知识地图与每个版本的知识稿 | **学习与复习用** |

约定：

- `vision.md` 写目标，`overview.md`、`design.md`、`rules/` 只写**当前已实现的系统**，随实现更新。
- 版本收尾时，提案中有长期价值的内容融入现行文档，提案本身移入 `archive/changes/`，顶部写实施结果与差异。`decisions/` 长期有效，被新决策取代时标注"已被取代"。
- 字段、枚举、接口细节以代码中的类型定义、自动生成的 API 文档和测试为准，不写进文档。
- 给人看的运行结果（评测页、审核页）在 `reports/`，不在 `docs/`。
